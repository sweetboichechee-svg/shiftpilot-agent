# ShiftPilot 通用智能排班 Agent

ShiftPilot 把自然语言需求、确定性约束求解和独立结果校验组合成一条可审计的排班链路。它面向门店、客服中心、仓储物流等需要处理技能、可用时间、工时和班次衔接的团队。

- 在线产品：https://sweetboichechee-svg.github.io/shiftpilot-agent/
- 解析服务：https://shiftpirser-api-tngcdhxlys.cn-beijing.fcapp.run/health
- 前端托管：GitHub Pages；模型网关：阿里云函数计算；模型：百炼 DeepSeek V4 Flash。

## 产品能力

- 自然语言输入临时请假、增员、指定班次、班次上限和偏好。
- 快速操作可直接选择员工、日期、请假时段、增员班次和人数；支持积累多条条件后统一求解。
- 通过阿里云百炼调用 DeepSeek，将业务描述转换为结构化约束。
- 每次点击“生成排班”先发起一次模型请求；“AI 解析”页展示模型、耗时、Token、请求 ID、结束原因与结构化输出，便于现场演示和问题排查。
- 大模型不直接生成班表；确定性求解器严格执行员工、技能、时间和工时规则。
- 求解后再次独立校验，并输出冲突证据、员工负载、成本和偏好匹配率。支持在班表中换人、重新校验和撤销。
- 成本明细按“员工时薪 × 班次工时”汇总，可追溯到每位员工。
- 内置零售门店、电商客服、仓配中心三个模板。
- 支持导入业务配置 JSON、员工 CSV 和需求 TXT，支持导出班表 CSV、配置 JSON 和员工模板。
- 百炼不可用时自动降级到本地规则解析，基础排班仍可运行。

## 本地运行

复制 `.env.example` 为 `.env.local`，在服务端填写百炼配置。API Key 不得放进网页代码或提交到 Git。

```bash
pnpm dev
```

默认模型是 `deepseek-v4-flash`。如果百炼账号尚未开通该模型，可在 `.env.local` 中修改 `DASHSCOPE_MODEL`，无需改代码。

完整应用需要可执行 `app/api/parse/route.ts` 的服务端运行环境。GitHub Pages 只能托管静态前端；独立部署解析服务时，将 `NEXT_PUBLIC_SCHEDULER_API_URL` 指向完整接口地址，并在服务端用 `ALLOWED_ORIGINS` 放行前端域名。API Key 始终只保存在服务端。未连接服务端时，页面会明确显示本地回退，不会伪造模型调用成功。

## 数据格式

业务配置使用 `ScheduleConfig` JSON，包含日期、班次、最低人数、技能要求、员工、可用日期、请假、偏好、工时、禁排衔接和成本策略。页面“业务配置”可直接查看并导出完整示例。

员工 CSV 字段为：

```text
id,name,role,skills,availableDayIds,leaveDayIds,preferredShiftIds,maxShifts,hourlyCost
```

同一字段内的多个值用 `|` 分隔。

## 架构

1. DeepSeek 只把自然语言解析为结构化增量约束。
2. 服务端先检查模型输出协议，客户端再拒绝未知员工、日期、班次，以及临时补技能或放宽硬规则的请求。
3. 求解器搜索满足全部硬约束的人员组合，再优化公平性、偏好和成本。
4. 独立校验器逐条复核最低人数、技能、可用时间、每日班次、周工时、连续工作、班次衔接和指定安排。

这种拆分让模型可以更换，也让每一份班表都有明确的规则依据。

## 三个内置场景

三个场景共享同一套“模型解析 → 约束求解 → 独立校验”引擎，区别在员工数据、班次、技能、最低人数和优化目标：

- **连锁咖啡门店 · 作业原题**：严格复现面试作业的 E01–E20、09:00–17:00 早班、13:00–21:00 晚班及 R-01～R-09。周一至周五每班至少 4 人，周六周日每班至少 6 人；校验页逐条显示 R-01～R-09，并额外检查每人每天最多一班。
- **电商客服中心**：使用 12 名客服，白班与中班分别要求组长、售前或售后技能，用于证明同一排班引擎可以迁移到服务团队。
- **区域仓配中心**：使用 12 名仓配员工，日班与晚班要求现场主管和叉车技能，并开启成本优化，用于展示技能稀缺和成本目标的组合。

只有第一个模板是作业原题的提交与验收场景；后两个属于通用产品扩展示例，不改变原题规则集，也不用于替代作业验收。
